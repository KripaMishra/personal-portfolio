## Context

The public README frames mastra-pii as a foundation release, not a finished privacy platform. That honesty is the strength of the project.

## Problem

Sensitive text can leak through prompts, traces, memory, retries, and exported artifacts. A privacy layer that looks broader than it really is can be more dangerous than a narrow layer with explicit limits.

## Constraints

The Alpha 1 scope rejects `ner` and `model` layers, avoids network calls during redaction, and refuses to claim perfect recall. This case study keeps those limits front and center.

## Approach

mastra-pii exposes a compact surface: async text redaction, a Processor-compatible integration point, deterministic placeholders, optional custom regexes, and fail-closed error handling. The design favors explainability and predictable local behavior over maximal coverage.

## Evidence

The portfolio uses the public README as the primary evidence source and keeps all example text synthetic.

## Decisions

A published ADR captures why the initial release locks in deterministic local behavior.

## Outcome / current state

The project is in development, but the public evidence already supports a concrete technical lesson: honest limits plus fail-closed behavior are part of the product value.
